3. Rigor choices (the clean-build fixes)

  1. Standardisation. Only numeric covariates are z-scored; the 0/1 dummies are never scaled. There are 12 numeric model columns, not 13: age is dropped because age = age_at_onset + disease_duration holds exactly (checked: max abs difference 0), and CTG enters as log10. The scaler is re-fitted on the training rows of every CV fold (sklearn: a ColumnTransformer inside each Pipeline, so inner GridSearchCV folds also refit it; R: scale_fit() inside every fit) and, for test scoring, on the full TRAIN set then applied to test. Trees, forests and XGBoost are invariant to per-column affine rescaling, so they receive the same pipeline output (stated, not tuned). glmnet is called with standardize=FALSE on that matrix, so dummies keep their natural 0/1 scale in the penalty. Constant-in-train columns are dropped (Mexiletine: albumin; Oligonucleotide and Tideglusib keep all 12).
  2. Train-only everywhere before the test pass. CV, selection, signal-vs-noise evidence, PCA and importance used in verdicts all use TRAIN rows only. Test features are exported only inside s07.
  3. Primary models by CV only. s05 picks, per arm and outcome, the best covariate model and the best ML model (tuned and untuned rows pooled) by repeated 5-fold x3 TRAIN CV (lowest RMSE for regression, highest ROC-AUC for the label) and records the CV value, the runner-up and the baseline in results/primary_selection.csv. Baselines are excluded from the pool.
  4. Nested tuning. Tuned rows run an inner 3-fold GridSearchCV on each outer fold's training rows, so CV scores of tuned models are not tuned on their own evaluation fold.

4. Test-once discipline

Disclosure. The main project already scored this same 80/20 test set once (its step 5, with different, frozen specifications). That file (results/step5_metrics.csv) was NOT read or used here. This canonical scoring selects primary models by TRAIN CV only and scores the full PDF-scope method set on the test set in a single pass (s07_test_scoring.py), after which results/TEST_SCORED.lock (timestamps, SHA-256 of the selection file) blocks any re-run unless --force / FORCE7=1 is given. The runner wipes results/ (including the lock) at the start, so a from-scratch run produces exactly one scoring pass; the pipeline is deterministic.

Test permutation importance and SHAP come from the very models scored in that pass (nothing refitted afterwards) and are explanatory only: they feed no selection and no verdict. While debugging s07 a code-only dry-run mode (DM1_DRYRUN=1) substitutes 30 TRAIN rows for the test rows, so the real test rows were not read during development. All test numbers are reported whatever they are; nothing was tuned or removed after seeing them.

5. Signal vs noise: the single pre-stated verdict rule

Applied unchanged to every arm and to both outcomes (continuous outcome; responder label). No second or relaxed rule exists. Evidence uses TRAIN rows only (r_signal.R, s06a_rf_null.py, s06_signal_noise.py). A covariate scores one point per criterion:

CriterionDefinition
(a) selection frequencypooled selection frequency ≥ 0.6 over three selectors (LASSO lambda.min, elastic net alpha=.5, stepwise-BIC both) in B=200 bootstrap resamples (cv.glmnet folds keep duplicated patients together)
(b) sign stabilitysign of the lm/glm coefficient equals the full-train sign in ≥ 4 of 5 train subsamples (each 80%, leave-one-fold-out)
(c) multi-family useused by ≥ 2 of 3 families on full train: penalised (LASSO or EN nonzero); stepwise-BIC retained; nonlinear/ML (GAM term p<0.05 under REML select=TRUE, or RF held-out permutation importance > 0 in ≥ 4/5 CV folds)
(d) beats shuffled-outcome nulllm/glm |t| (|z|) above the 95th percentile of its own null from 500 outcome permutations, OR RF held-out permutation importance above the 95th percentile of the RF null from 100 outcome permutations

SIGNAL = all four; NOISE = 0 or 1 of 4; BORDERLINE = 2 or 3. Wording deviation: the brief says "GAM edf>1"; a smooth with edf near 1 is a straight-line effect that edf>1 would exclude, so the GAM family test is the term's p<0.05 (edf is reported alongside). Direction = sign of the full-train standardised lm/glm coefficient, translated to benefit (Mexiletine outcome: negative = better; label: Responder = better). Prior signs are transcribed from the hypothesis sheet in src/priors.py before looking at results; "n/a (prior open)" means the sheet gives no direction. Plausible-but-noise flags: among NOISE covariates, those listed by the sheet as plausible-looking noise first, then by prior strength (strong, moderate, weak); at most one dummy per parent covariate; top 3 per arm and outcome, each with an auto-generated one-line reason carrying its numbers. Verdicts are at feature level (dummy levels are separate rows).

7. Development log (what was learnt)

  • A first signal run froze the bootstrap: set.seed(1) inside cv.glmnet helper reset the RNG every iteration, so every resample was identical and selection frequencies were 0 or 1. Fixed by passing a fixed fold id inside the bootstrap (no RNG reset); results regenerated before any verdict was read.
  • Mexiletine's albumin is constant in train and is dropped; the stepwise-BIC and best-subset fits coincide for Oligonucleotide continuous outcome (same model chosen).
  • GAM fits on the label sometimes warn "step failure" from mgcv's Newton step; predictions were still produced (no NA predictions in any CV fit).
