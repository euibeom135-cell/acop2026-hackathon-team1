dm1_hackathon_r.zip vs the long R file (dm1_analysis_onefile.R) vs our analysis

The zip's six scripts were run unchanged except for the one line the README tells you to edit (arm_name), once per arm (02, 03, 04), then 05. All finished without errors. Dataset identical. Each pipeline uses its own 75/25 split (zip: seed 2026 stratified by label; onefile: seed 20261011 stratified by label and phenotype), so test patients differ and single-split numbers differ by noise. Output: dm1_hackathon_r/results/.

3. Differences and flags

  • Age instead of disease duration. The zip drops disease_duration and keeps age (and age_at_onset). Age is the sum of onset age and duration, so it then appears as a secondary pick (Mexiletine 4/6, Oligonucleotide 4/6); our analysis keeps onset and duration instead and finds duration for Tideglusib. These are the same information in different coordinates.
  • Cutoff 0.5 for the responder label. Recall is 0.00 for elastic net (Mexiletine, Oligonucleotide) and tuned XGBoost (Mexiletine): with 29-41% responders almost nobody is called a responder at 0.5, so accuracy/recall/precision are hard to compare; AUC is unaffected. The onefile and our analyses use a cutoff matched to the training responder share.
  • Stepwise AIC is unstable: Tideglusib continuous R² -0.01 (CI -0.43 to 0.27) versus stepwise BIC 0.20, the instability the kickoff guide warns about.
  • Untuned XGBoost is worst or near-worst in Oligonucleotide (R² -0.25); tuned XGBoost recovers it, matching the 'tuning helps on small data only sometimes' message.
  • Method sets differ: the zip has best subset but no plain LASSO; the onefile has LASSO and a cut-off model; ours covers every method in the kickoff guide.

Verdict

Yes, similar. Same drivers, same arm ordering of predictability and, within the noise of a single ~40-patient test set, similar scores. The zip's pipeline is also internally consistent with ours on which methods are stable and which are not.
